# Завантаження зображень через serper.dev — специфікація для відтворення

Документ описує, як у Yo Journey Builder (Step 3, «Парсинг фото») працює пошук і завантаження
фото товарів через Google Images API від **serper.dev**. Мета — щоб інший агент міг повторити
функціонал в іншому проєкті 1:1.

Джерела в цьому репо:
- `download.py` — HTTP-запит до serper, завантаження та збереження фото
- `main.py:253-358` — оркестрація (`download_images`)
- `utils.py` — `read_excel_rows`, `cell_text`
- `app_paths.py` — назви папок, конфіг

---

## 1. Загальна схема

```
Excel (лист «Шаблон») ─► список артикулів
        │
        ├─► фільтр: прибрати артикули, які вже є підпапками в папці «бот/»
        │
        ├─► ЕТАП 1 — ПОШУК: пачками по 100 артикулів → POST https://google.serper.dev/images
        │       ← масив результатів, по одному на кожен запит у пачці
        │       → фільтр за розміром, формування імені файлу → список задач (url, папка, ім'я)
        │
        └─► ЕТАП 2 — ЗАВАНТАЖЕННЯ: пул з 16 потоків, кожна задача:
                GET url (без проксі) → якщо помилка і є проксі → GET через проксі
                → Pillow → RGB → JPEG quality=100 → <base>/downloaded-images/<артикул>/<ім'я>.jpg
```

Ключова ідея: **спочатку збираємо всі посилання (швидко, мало запитів), потім паралельно качаємо**.

## 2. Вхідні параметри

| Параметр  | Звідки                          | Обов'язковий | Опис |
|-----------|----------------------------------|--------------|------|
| `api_key` | поле UI, зберігається в config.json | так | ключ serper.dev, передається в заголовку `X-API-KEY` |
| `region`  | поле UI (напр. `ua`)             | ні | код країни Google → параметр `gl`. Порожній рядок → `None` (параметр не передається) |
| `proxy`   | поле UI, config.json             | ні | `http://user:pass@host:port`; використовується **тільки як fallback** при завантаженні фото (не для запиту до serper) |
| `base_dir`| config.json                      | так | основна робоча директорія |
| `excel_path` | config.json                   | так | Excel-файл з листом `Шаблон` |

Усі три значення (`api_key`, `region`, `proxy`) зберігаються в `config.json` при кожній зміні поля
і при запуску операції, тож при наступному запуску підставляються автоматично.

## 3. Читання артикулів з Excel

- Файл відкривається через `openpyxl.load_workbook(path, read_only=True, data_only=True)`.
- Лист: **`Шаблон`** (якщо немає — помилка «Лист 'Шаблон' не знайдено»).
- Пропускається перший рядок (заголовок), читається з `min_row=2`.
- Колонки (індекси з 0):

| Індекс | Колонка Excel | Поле          | Використання |
|--------|---------------|---------------|--------------|
| 0      | A             | `code`        | артикул; рядки з порожнім артикулом пропускаються |
| 2      | C             | `name`        | назва товару, йде в пошуковий запит |
| 5      | F             | `prod_type`   | тип товару → в ім'я файлу |
| 7      | H             | `prod_gender` | зчитується, але зараз не використовується |
| 9      | J             | `prod_brand`  | бренд → в ім'я файлу |

- Нормалізація значення комірки (`cell_text`):
  - `None` → `""`
  - float з цілим значенням (`12345.0`) → `"12345"` (важливо: артикули-числа Excel віддає як float)
  - інакше `str(value).strip()`

Якщо після читання список порожній — помилка «На листі 'Шаблон' немає артикулів».

---

## 4. Фільтр «вже є в боті»

- В `base_dir` шукається папка з назвою `бот` або `bot` (порівняння `strip().casefold()`, регістр не важливий).
- Якщо знайдена — збираються назви всіх її **підпапок** (`strip().casefold()`).
- З списку артикулів прибираються ті, у яких `code.casefold()` збігається з назвою підпапки.
- Кількість пропущених рахується для фінального повідомлення.
- Якщо після фільтра нічого не лишилось — помилка «Усі артикули вже є в папці «бот», парсити нічого».
- Якщо папки `бот` немає — парсяться всі артикули (і про це пишеться у фінальному повідомленні).

## 5. Етап 1 — запит до serper.dev

### 5.1. Endpoint

```
POST https://google.serper.dev/images
Headers:
  X-API-KEY: <api_key>
  Content-Type: application/json
Timeout: 60 c
```

### 5.2. Пакетний (batch) запит

serper.dev приймає в тілі **JSON-масив** запитів — один HTTP-виклик обробляє одразу багато пошуків.
Артикули розбиваються на пачки по **100** (`SEARCH_CHUNK = 100`).

Тіло для пачки:

```json
[
  {"q": "123456 Кросівки Nike Air Max", "gl": "ua"},
  {"q": "123457 Черевики Timberland",   "gl": "ua"}
]
```

- `q` = `f"{code} {name}"` — **артикул завжди першим словом**, далі назва через пробіл.
  Це критично: з відповіді артикул відновлюється як перше слово `q` (див. 5.4).
- `gl` додається тільки якщо region заданий.
- `num`, `hl`, `page` не передаються → serper повертає дефолтну кількість фото на запит.
  (За потреби можна додати `"num": N`.)

Реалізація (Python, stdlib):

```python
import http.client, json

def req(params, key):
    conn = http.client.HTTPSConnection("google.serper.dev", timeout=60)
    headers = {"X-API-KEY": key, "Content-Type": "application/json"}
    conn.request("POST", "/images", json.dumps(params), headers)
    res = conn.getresponse()
    data = res.read().decode("utf-8")
    if res.status != 200:
        raise RuntimeError(f"serper.dev відповів {res.status}: {data[:200]}")
    return data
```

Статус ≠ 200 → виняток, **вся операція переривається** (помилка показується користувачу,
напр. невалідний ключ / закінчились кредити).

### 5.3. Формат відповіді

Масив об'єктів у тому ж порядку, що й запити:

```json
[
  {
    "searchParameters": {"q": "123456 Кросівки Nike Air Max", "gl": "ua", "type": "images", "engine": "google"},
    "images": [
      {
        "title": "...",
        "imageUrl": "https://example.com/full.jpg",
        "imageWidth": 1200,
        "imageHeight": 800,
        "thumbnailUrl": "https://encrypted-tbn0.gstatic.com/...",
        "thumbnailWidth": 275,
        "thumbnailHeight": 183,
        "source": "Example Shop",
        "domain": "example.com",
        "link": "https://example.com/product",
        "googleUrl": "https://www.google.com/imgres?...",
        "position": 1
      }
    ]
  }
]
```

Використовуються поля: `searchParameters.q`, `images[].imageUrl`, `imageWidth`, `imageHeight`, `position`.

### 5.4. Обробка відповіді → список задач

Для кожного елемента відповіді (обгорнуто в try/except — помилка одного елемента лише збільшує
лічильник `errors`, решта обробляється):

1. `code = item["searchParameters"]["q"].split(" ")[0]` — артикул з першого слова запиту.
   ⚠️ Якщо артикул містить пробіли — зламається; в новій реалізації краще зіставляти за
   індексом у пачці (`zip(chunk, response)`), бо порядок відповідей збігається з порядком запитів.
2. `descr` = дані артикула (dict `code → item`), або `{}` якщо не знайдено.
3. Цільова папка: `<base_dir>/downloaded-images/<code>/`.
4. Для кожного `img` у `item.get("images", [])`:
   - **Фільтр розміру:** пропустити, якщо `imageWidth < 351 AND imageHeight < 351`
     (тобто відкидаються тільки фото, у яких **обидві** сторони менші за 351 px;
     якщо хоча б одна сторона ≥ 351 — фото береться).
   - `uid` = випадкове число 0–999, з нулями до 3 цифр (`f"{random.randint(0, 999):03d}"`) —
     щоб імена не збігались при повторних запусках.
   - Ім'я файлу (без розширення):
     ```
     {position}___{code}___{W}x{H}__{prod_type}__{prod_brand}__{region}__{uid}
     ```
     Роздільники: **3** підкреслення після `position` і після `code`, далі **2** підкреслення.
     Приклад: `1___123456___1200x800__Кросівки__Nike__ua__042.jpg`
     Якщо region не задано — в імені буде буквально `None`; якщо тип/бренд відсутні — теж `None`.
   - Додати задачу `(code, imageUrl, target_dir, name)`.

Прогрес етапу 1: від 3% до 15%, крок на кожну пачку, текст «Пошук фото: X з N».

## 6. Етап 2 — паралельне завантаження

### 6.1. Пул потоків

- `ThreadPoolExecutor(max_workers=16)` (`DOWNLOAD_WORKERS = 16`).
- Усі задачі сабмітяться одразу; головний потік у циклі чекає `wait(pending, timeout=0.2, return_when=FIRST_COMPLETED)`,
  на кожну завершену задачу оновлює прогрес і викликає `eel.sleep(0)`, щоб UI (Eel/gevent) не зависав.
  В іншому фреймворку — просто будь-який неблокуючий спосіб оновлювати прогрес.
- Прогрес: від 15% до 99%, текст «Завантажено X з N (<code>)».
- Успіх рахується, якщо функція повернула шлях; `None` або виняток → не рахується (виняток → `errors += 1`).

### 6.2. Завантаження одного фото

```python
import os, requests
from io import BytesIO
from PIL import Image

def download_image(url, save_dir, filename, proxy=None):
    os.makedirs(save_dir, exist_ok=True)
    proxies = {"http": proxy, "https": proxy} if proxy else None

    def get_image(use_proxy):
        response = requests.get(url, timeout=20, proxies=proxies if use_proxy else None)
        response.raise_for_status()
        img = Image.open(BytesIO(response.content))
        return img.convert("RGB") if img.mode != "RGB" else img

    try:
        img = get_image(False)                 # 1) без проксі
    except Exception as first_error:
        if not proxies:
            return None
        try:
            img = get_image(True)              # 2) повтор через проксі
        except Exception:
            return None

    save_path = os.path.join(save_dir, f"{filename}.jpg")
    img.save(save_path, "JPEG", quality=100)
    return save_path
```

Поведінка:
- Timeout на одне фото — 20 с.
- Будь-яка помилка (мережа, 4xx/5xx, не-зображення, яке Pillow не відкриває) → спроба через проксі,
  якщо він заданий; інакше пропуск (повертає `None`, лог у консоль).
- Будь-який формат (PNG з прозорістю, WebP, GIF, CMYK…) конвертується в RGB і зберігається як **JPEG quality=100**.
- Розширення завжди `.jpg`. Існуючий файл з таким же ім'ям перезаписується (на практиці не трапляється завдяки `uid`).
- Заголовки (User-Agent тощо) не задаються — дефолтні `requests`. Якщо в новому середовищі багато 403 —
  варто додати браузерний `User-Agent`.

## 9. Відомі нюанси / що можна покращити при перенесенні

1. **Зіставлення відповіді з артикулом** через `q.split(" ")[0]` — краще за індексом у пачці.
2. **Помилка однієї пачки serper** (не 200, таймаут) перериває всю операцію — можна ловити й продовжувати.
3. `region=None` / відсутні тип чи бренд дають `None` в імені файлу — можна замінити на порожній рядок.
4. Немає дедуплікації однакових `imageUrl` у межах артикула.
5. Немає повторів (retry) окрім fallback через проксі.
6. `prod_gender` зчитується, але не використовується.
7. Проксі не застосовується до запиту в serper.dev — тільки до завантаження самих фото.
